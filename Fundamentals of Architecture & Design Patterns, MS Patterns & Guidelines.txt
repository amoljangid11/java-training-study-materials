Singleton Pattern :

Ensures only one object exists.

Example :

public class DatabaseConnection {

    private static DatabaseConnection instance;

    private DatabaseConnection() {
    }

    public static synchronized DatabaseConnection getInstance() {

        if(instance == null) {
            instance = new DatabaseConnection();
        }

        return instance;
    }
}

Usage:

DatabaseConnection obj1 = DatabaseConnection.getInstance();
DatabaseConnection obj2 = DatabaseConnection.getInstance();

System.out.println(obj1 == obj2);

Output:

true

Factory Pattern :

Creates objects without exposing creation logic.

Example
Interface

public interface Notification {
    void send();
}

Email

public class EmailNotification implements Notification {

    @Override
    public void send() {
        System.out.println("Email Sent");
    }
}

SMS

public class SMSNotification implements Notification {

    @Override
    public void send() {
        System.out.println("SMS Sent");
    }
}

Factory

public class NotificationFactory {

    public static Notification createNotification(String type) {

        if(type.equalsIgnoreCase("EMAIL"))
            return new EmailNotification();

        if(type.equalsIgnoreCase("SMS"))
            return new SMSNotification();

        return null;
    }
}

Usage:

Notification notification =
        NotificationFactory.createNotification("EMAIL");

notification.send();

Builder Pattern :

Useful for creating complex objects.

Example :

public class Employee {

    private String name;
    private int age;
    private String city;

    private Employee(EmployeeBuilder builder){
        this.name = builder.name;
        this.age = builder.age;
        this.city = builder.city;
    }

    public static class EmployeeBuilder {

        private String name;
        private int age;
        private String city;

        public EmployeeBuilder setName(String name){
            this.name = name;
            return this;
        }

        public EmployeeBuilder setAge(int age){
            this.age = age;
            return this;
        }

        public EmployeeBuilder setCity(String city){
            this.city = city;
            return this;
        }

        public Employee build(){
            return new Employee(this);
        }
    }
}

Usage:

Employee emp = new Employee.EmployeeBuilder()
        .setName("John")
        .setAge(30)
        .setCity("Pune")
        .build();

Strategy Pattern :

Encapsulates algorithms.

Example :

public interface PaymentStrategy {
    void pay(double amount);
}
public class CreditCardPayment
        implements PaymentStrategy {

    @Override
    public void pay(double amount) {
        System.out.println("Paid using Card");
    }
}
public class UpiPayment
        implements PaymentStrategy {

    @Override
    public void pay(double amount) {
        System.out.println("Paid using UPI");
    }
}

Context:

public class PaymentContext {

    private PaymentStrategy strategy;

    public PaymentContext(PaymentStrategy strategy){
        this.strategy = strategy;
    }

    public void process(double amount){
        strategy.pay(amount);
    }
}

Usage:

PaymentContext context =
        new PaymentContext(new UpiPayment());

context.process(5000);

3. 12-Factor Methodology

Developed by engineers at Heroku.

Provides best practices for cloud-native applications.

Why 12-Factor?

Helps build:

Scalable apps
Cloud-native apps
Microservices
Containerized applications

Factor 1: Codebase

One codebase tracked in Git.

One Application
One Repository

Example:

git clone employee-service

Factor 2: Dependencies

Explicitly declare dependencies.

Maven:

<dependency>
    <groupId>org.springframework.boot</groupId>
</dependency>

Never rely on system-installed libraries.

Factor 3: Config

Store configuration outside code.

Bad:

String dbPassword = "root123";

Good:

spring.datasource.password=${DB_PASSWORD}

Environment Variable:

DB_PASSWORD=root123

Factor 4: Backing Services

Treat services as attached resources.

Examples:

MySQL
PostgreSQL
Redis
Kafka

Configuration change only.

spring.datasource.url=...

Factor 5: Build, Release, Run

Separate stages.

Build
  |
Release
  |
Run

Example:

mvn clean package

Factor 6: Processes

Run application as stateless processes.

Bad:

static Map<String,Object> cache

Good:

Redis
Database

Factor 7: Port Binding

Export services via ports.

server.port=8080

Application self-contained.

Factor 8: Concurrency

Scale using processes.

Instance1
Instance2
Instance3

Docker/Kubernetes scale horizontally.

Factor 9: Disposability

Fast startup and graceful shutdown.

@PreDestroy
public void shutdown() {
}

Useful in Kubernetes.

Factor 10: Dev/Prod Parity

Keep environments similar.

Developer
QA
Production

Use Docker to maintain consistency.

Factor 11: Logs

Treat logs as event streams.

log.info("Order Created");

Logs sent to:

ELK Stack
Splunk
Grafana Loki

Factor 12: Admin Processes

Run one-off admin tasks separately.

Example:

java -jar app.jar migration

Database migration:

Flyway
Liquibase
