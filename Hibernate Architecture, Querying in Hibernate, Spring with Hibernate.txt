Explain Hibernate Architecture, Learn the Hibernate API-Configuration :


What is Hibernate?

Hibernate ORM is an Object Relational Mapping (ORM) framework used in Java to simplify database operations.

It maps:

Java Classes ➜ Database Tables
Java Objects ➜ Table Records
Java Data Types ➜ SQL Data Types

Hibernate removes the need to write most JDBC code manually.

Why Hibernate?

Problems with JDBC

Using JDBC directly requires:

Writing SQL queries manually
Managing connections
Handling ResultSet conversions
Transaction management
Boilerplate code

Hibernate solves these problems by:

Providing ORM support
Automatic table mapping
Caching
Transaction management

HQL (Hibernate Query Language)

Loads Hibernate configuration file

Features :

Heavyweight object
Created only once
Thread-safe
Maintains second-level cache

A Session object represents a connection between Java application and database.

Responsibilities

CRUD operations

Manage persistent objects

1. What is SessionFactory in Hibernate?

Definition

SessionFactory is a heavyweight object responsible for creating Session objects.

Factory Object	Creates Session objects
Immutable	Configuration cannot change after creation

       ↓

       ↓

3. What is OR Mapping in Hibernate?

OR Mapping Meaning

ORM stands for:

Object Relational Mapping

It is a technique used to map:

Java Class → Database Table
Java Object → Row
Variables → Columns

Mapping Relationship

Java Side	Database Side
Class	Table
Object	Row
Attribute	Column

Object ID	Primary Key

Example

Java Class
public class Student {

    private int id;
    private String name;
}
Database Table
CREATE TABLE student(
   id INT PRIMARY KEY,
   name VARCHAR(100)
);

Hibernate automatically maps:

Student → student
id → id
name → name


Types of ORM Mapping in Hibernate

1. Basic Mapping

Maps simple fields.

@Column(name="student_name")
private String name;

2. Primary Key Mapping

@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private int id;

3. One-to-One Mapping

One record related to one record.

Example

One Person → One Passport

@OneToOne
private Passport passport;

4. One-to-Many Mapping

One parent has many children.

Example

One Department → Many Employees

@OneToMany
private List<Employee> employees;

5. Many-to-One Mapping

Many records belong to one parent.

Example
Many Employees → One Department

@ManyToOne
private Department department;

6. Many-to-Many Mapping

Many records related to many records.

Example
Students ↔ Courses

@ManyToMany
private List<Course> courses;

Hibernate Object States :

In Hibernate, every entity object goes through different states during its lifecycle.

There are mainly 3 important object states:

Transient State
Persistent State
Detached State

1️. Transient State :

Definition

An object is in a Transient State when:

It is created using new keyword
It is NOT associated with Hibernate Session
It is NOT stored in database

Example

Student s = new Student();

s.setName("Amol");
s.setCourse("Java");

Explanation :

Object exists only in JVM memory
Hibernate does not track it
No database record created

Diagram

new Object()
     ↓
Transient State

2️. Persistent State

Definition

An object becomes Persistent when:

It is associated with Hibernate Session
Hibernate tracks changes automatically
Data exists in database

Example

Session session = factory.openSession();

Transaction tx = session.beginTransaction();

Student s = new Student();
s.setName("Rahul");
s.setCourse("Spring");

session.save(s);

tx.commit();
session.close();

What Happens Internally?

Object + Session Association
            ↓
Persistent State
            ↓
Hibernate tracks object
            ↓
INSERT query executed

Important Points

Changes are automatically synchronized to database
Hibernate manages object lifecycle
Object is attached to Session

3️. Detached State

Definition

An object becomes Detached when:

Session is closed
Object was previously persistent
Hibernate no longer tracks it

Example

Session session = factory.openSession();

Student s = session.get(Student.class, 1);

session.close(); // detached state

Diagram

Persistent Object
       ↓
Session Closed
       ↓
Detached Object

Important Points

Object still contains data
Changes are NOT saved automatically
Must reattach using update() or merge()

Hibernate Object State Lifecycle

new Object()
    ↓
Transient
    ↓ save()
Persistent
    ↓ session.close()
Detached
    ↓ update()
Persistent Again

Database dependent	Database independent

2️. Types of HQL Queries

A) Fetch All Records

HQL Query

String hql = "from Student";

Query<Student> query = session.createQuery(hql, Student.class);

List<Student> students = query.list();

for(Student s : students) {
    System.out.println(
        s.getId() + " " +
        s.getName() + " " +
        s.getCourse() + " " +
        s.getMarks()
    );
}

Generated SQL

B) Fetch Specific Columns

String hql = "select name, course from Student";

Query<Object[]> query = session.createQuery(hql, Object[].class);

List<Object[]> list = query.list();

for(Object[] obj : list) {
    System.out.println(obj[0] + " " + obj[1]);
}

C) WHERE Clause Example

String hql = "from Student where course='Java'";

Query<Student> query = session.createQuery(hql, Student.class);

List<Student> list = query.list();

}

3️. Querying with Criteria API

What is Criteria API?

Criteria API is used to create queries dynamically using Java objects instead of writing HQL manually.

It is:

Type-safe
Dynamic
Flexible

Used heavily in enterprise applications.

Criteria API Flow :

Session
   ↓
CriteriaBuilder
   ↓
CriteriaQuery
   ↓
Root
   ↓
Execute Query

A) Fetch All Records using Criteria API

Session session = factory.openSession();

CriteriaBuilder cb = session.getCriteriaBuilder();

CriteriaQuery<Student> cq =
        cb.createQuery(Student.class);

Root<Student> root = cq.from(Student.class);

cq.select(root);

Query<Student> query = session.createQuery(cq);

List<Student> list = query.getResultList();

for(Student s : list) {
    System.out.println(s.getName());
}

B) WHERE Condition using Criteria API

CriteriaBuilder cb = session.getCriteriaBuilder();

CriteriaQuery<Student> cq =
        cb.createQuery(Student.class);

Root<Student> root = cq.from(Student.class);

cq.select(root)
  .where(cb.equal(root.get("course"), "Java"));

Query<Student> query = session.createQuery(cq);

List<Student> list = query.getResultList();

for(Student s : list) {
    System.out.println(s.getName());
}

C) Multiple Conditions

cq.select(root)
  .where(
      cb.and(
          cb.equal(root.get("course"), "Java"),
          cb.gt(root.get("marks"), 80)
      )
  );

D) ORDER BY using Criteria API

cq.select(root)
  .orderBy(cb.desc(root.get("marks")));

E) LIKE Operator
cq.select(root)
  .where(cb.like(root.get("name"), "A%"));
F) Aggregate Function using Criteria API
Count Students
CriteriaQuery<Long> cq =
        cb.createQuery(Long.class);

Root<Student> root = cq.from(Student.class);

cq.select(cb.count(root));

Long count = session.createQuery(cq)
                    .getSingleResult();

System.out.println(count);
G) Pagination Example
Query<Student> query = session.createQuery(cq);

query.setFirstResult(0);
query.setMaxResults(2);

List<Student> list = query.getResultList();

HQL vs Criteria API
Feature	HQL	Criteria API
Query Style	String-based	Object-based
Readability	Easy	Moderate
Dynamic Query	Difficult	Excellent
Compile-time Safety	No	Yes
Best For	Static queries	Dynamic queries
When to Use HQL?

Use HQL when:

Queries are fixed
Simpler queries are required
Faster development is needed

Example:

from Student where course='Java'
When to Use Criteria API?

Use Criteria API when:

Queries are dynamic
Search filters change frequently
Enterprise-level applications
Runtime conditions

Example:

if(course != null) {
   predicates.add(
      cb.equal(root.get("course"), course)
   );
}

package com.example.entity;

import javax.persistence.*;

@Entity
@Table(name = "employee")
public class Employee {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private int id;

    private String name;

    private String department;

    private double salary;

    public Employee() {
    }

    public Employee(String name, String department, double salary) {
        this.name = name;
        this.department = department;
        this.salary = salary;
    }

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getDepartment() {
        return department;
    }

    public void setDepartment(String department) {
        this.department = department;
    }

        return salary;

                "id=" + id +
                ", name='" + name + '\'' +
                ", department='" + department + '\'' +
                ", salary=" + salary +
                '}';
    }
}
9. Spring Configuration Class
AppConfig.java
package com.example.config;

import java.util.Properties;

import javax.sql.DataSource;

import org.hibernate.SessionFactory;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.ComponentScan;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.io.ClassPathResource;
import org.springframework.jdbc.datasource.DriverManagerDataSource;
import org.springframework.orm.hibernate5.HibernateTransactionManager;
import org.springframework.orm.hibernate5.LocalSessionFactoryBean;
import org.springframework.transaction.annotation.EnableTransactionManagement;

@Configuration
@EnableTransactionManagement
@ComponentScan(basePackages = "com.example")
public class AppConfig {

    @Bean
    public DataSource dataSource() {

        DriverManagerDataSource ds =
                new DriverManagerDataSource();

        ds.setDriverClassName("com.mysql.cj.jdbc.Driver");
        ds.setUrl("jdbc:mysql://localhost:3306/spring_hibernate_db");
        ds.setUsername("root");
        ds.setPassword("root");

        return ds;
    }

    @Bean
    public LocalSessionFactoryBean sessionFactory() {

        LocalSessionFactoryBean factory =
                new LocalSessionFactoryBean();

        factory.setDataSource(dataSource());

        factory.setPackagesToScan("com.example.entity");

        factory.setHibernateProperties(hibernateProperties());

        return factory;
    }

    private Properties hibernateProperties() {

        Properties properties = new Properties();

        properties.put("hibernate.dialect",
                "org.hibernate.dialect.MySQL8Dialect");

        properties.put("hibernate.show_sql", true);

        properties.put("hibernate.format_sql", true);

        properties.put("hibernate.hbm2ddl.auto", "update");

        return properties;
    }

    @Bean
    public HibernateTransactionManager transactionManager(
            SessionFactory sessionFactory) {

        HibernateTransactionManager tx =
                new HibernateTransactionManager();

        tx.setSessionFactory(sessionFactory);

        return tx;
    }
}

11. DAO Implementation
EmployeeDAOImpl.java
package com.example.dao;

import java.util.List;

import org.hibernate.Session;
import org.hibernate.SessionFactory;
import org.hibernate.query.NativeQuery;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Repository;
import org.springframework.transaction.annotation.Transactional;

import com.example.entity.Employee;

@Repository
@Transactional
public class EmployeeDAOImpl implements EmployeeDAO {

    @Autowired
    private SessionFactory sessionFactory;

    @Override
    public void saveEmployee(Employee employee) {

        Session session =
                sessionFactory.getCurrentSession();

        session.save(employee);

        System.out.println("Employee Saved");
    }

    @Override
    public List<Employee> getAllEmployees() {

        Session session =
                sessionFactory.getCurrentSession();

        return session.createQuery(
                "from Employee", Employee.class)
                .list();
    }

    @Override
    public Employee getEmployeeById(int id) {

        Session session =
                sessionFactory.getCurrentSession();

        return session.get(Employee.class, id);
    }

    @Override
    public void updateEmployee(Employee employee) {

        Session session =
                sessionFactory.getCurrentSession();

        session.update(employee);

        System.out.println("Employee Updated");
    }

    @Override
    public void deleteEmployee(int id) {

        Session session =
                sessionFactory.getCurrentSession();

        Employee emp =
                session.get(Employee.class, id);

        if(emp != null) {

            session.delete(emp);

            System.out.println("Employee Deleted");
        }
    }

    @Override
    public List<Employee> getEmployeesUsingNativeSQL() {

        Session session =
                sessionFactory.getCurrentSession();

        String sql =
                "SELECT * FROM employee";

        NativeQuery<Employee> query =
                session.createNativeQuery(
                        sql,
                        Employee.class);

        return query.getResultList();
    }
}
