Define Persistence, Identify the problems with OR Mismatch, Describe alternatives for Object/Relational Mapping(ORM) :


What is Persistence?

Persistence means storing the data permanently so that it can be retrieved and used later, even after the application is closed or the system is restarted.

In simple words:

Data created in memory (RAM) is temporary.
Persistent data is stored in databases, files, or storage systems permanently.
Example

Suppose an e-commerce application stores:

User details
Orders
Products
Payments

If the server shuts down and the data still exists in the database, that data is persistent.

Why Persistence is Needed?

Applications need persistence because:

Data must survive application shutdown
Multiple users need shared access
Historical records are required
Reporting and analytics need stored data
Business transactions must be reliable
Types of Persistence Storage
1. Relational Databases (Most Common)

Examples:

Oracle Corporation Oracle Database
MySQL MySQL

Microsoft SQL Server

Data stored in:

Tables
Rows
Columns
2. NoSQL Databases

Examples:

MongoDB MongoDB
Apache Cassandra Cassandra

Data stored as:

Documents

Graphs
3. File Systems

Examples:

XML files
JSON files
Text files
What is Object Relational Mapping (ORM)?

ORM is a technique that maps:

Object-Oriented Concepts	Relational Database Concepts
Class	Table
Object	Row
Attribute	Column
Object Relationship	Foreign Key Relationship

ORM allows developers to work with objects instead of writing SQL manually.

Example Without ORM
String sql = "INSERT INTO employee VALUES(1,'John')";

Developer manually writes SQL.

Example With ORM
Employee emp = new Employee();
emp.setName("John");

session.save(emp);

ORM automatically converts object into SQL query.

Object-Relational Mismatch (OR Mismatch)
Definition

Object-Oriented Programming and Relational Databases work differently.

This difference creates problems called:

Object-Relational Impedance Mismatch
Problems with OR Mismatch
1. Granularity Problem
Issue

Objects may contain complex structures, but relational tables store flat rows.

Example
Java Object
class Address {
    String city;
    String state;
    String pin;
}

class Employee {
    int id;
    String name;
    Address address;
}
Database Table
id	name	city	state	pin

Complex object becomes flattened.

2. Identity Problem
Issue

Objects use memory identity.

Database uses primary keys.

Example
Employee e1 = new Employee();
Employee e2 = new Employee();

Both are different objects in memory.

But in database:

Employee_ID = 101

ORM must synchronize both identities.

3. Inheritance Problem
Issue

OOP supports inheritance.

Relational databases do not support inheritance directly.

Example
class Vehicle {}

class Car extends Vehicle {}
class Bike extends Vehicle {}

How should tables be designed?

Possible solutions:

Single table
Multiple tables
Joined tables

ORM frameworks manage these strategies.

4. Association Problem
Issue

Objects use references.

Databases use foreign keys.

Example
Object Reference
Employee emp = department.getEmployee();
Database Relationship
EMPLOYEE(DEPT_ID)

ORM converts object references into joins.

5. Navigation Problem
Issue

Objects navigate directly through references.

Databases require joins.

Example
Object Navigation
student.getCourse().getTrainer()
Database Query
SELECT *
FROM STUDENT S
JOIN COURSE C
ON S.COURSE_ID = C.ID
JOIN TRAINER T
ON C.TRAINER_ID = T.ID

ORM handles this conversion.

6. Data Type Mismatch
Issue

Programming language data types differ from SQL types.

Example
Java Type	SQL Type
String	VARCHAR
boolean	BIT
Date	DATE/TIMESTAMP

ORM performs conversions automatically.

7. Lifecycle Management Problem
Issue

Objects have lifecycle controlled by application memory.

Database rows exist independently.

Example
Employee emp = new Employee();

Object may exist temporarily.

But database row may exist forever.

ORM manages persistence states:

Transient
Persistent
Detached
Removed
8. Performance Problems
Common ORM Performance Issues
N+1 Query Problem

ORM may generate excessive SQL queries.

Example

Fetching 1 department and 100 employees may create:

1 query for department
100 queries for employees

Total:
101 queries

9. Transaction Management Complexity

ORM must maintain:

Consistency
Rollback
Commit
Concurrency

between objects and database tables.

Alternatives for Object/Relational Mapping (ORM)

There are several alternatives to traditional ORM frameworks.

1. JDBC (Direct SQL Approach)
Description

Developer writes SQL manually.

Example

PreparedStatement ps =
con.prepareStatement(
"INSERT INTO employee VALUES(?,?)");

ps.setInt(1,101);
ps.setString(2,"John");

Full SQL control
Better performance tuning
Simpler for small applications
Disadvantages
Large amount of boilerplate code
Manual mapping
Harder maintenance
2. SQL Mapper Frameworks

Examples:

MyBatis MyBatis
Description

Developer writes SQL manually.

Framework maps result sets to objects.

Example

SELECT * FROM employee
</select>
Advantages
Better SQL control
Easier optimization
Less magic
Disadvantages
SQL maintenance required
More manual effort
3. Stored Procedures
Description

Business logic stored inside database.

Example
CREATE PROCEDURE getEmployees()
BEGIN
SELECT * FROM employee;
END;
Advantages
High performance
Centralized logic
Reduced network calls
Disadvantages
Database dependency
Hard to maintain large logic
4. NoSQL Databases

Examples:

MongoDB MongoDB

Description

Data stored as:

Documents

Key-value

No relational mapping needed.

Advantages

Disadvantages

5. Micro ORM

Examples:

Dapper Dapper
Description

Lightweight ORM.

Provides simple object mapping without full ORM complexity.

Advantages
Fast performance

Disadvantages
Fewer automation features

Description

Developers create their own persistence layer.

Example

Explain Hibernate as a preferred solution for ORM :


1. What is ORM?

ORM stands for Object Relational Mapping.

It is a technique used to map:

Java Objects → Database Tables
Class Fields → Table Columns

ORM helps developers work with databases using Java objects instead of writing large amounts of SQL queries manually.

2. What is Hibernate?

Hibernate ORM is a popular Java-based ORM framework used to simplify database operations in enterprise applications.

It acts as a bridge between:

Java Application
Relational Database (MySQL, Oracle, PostgreSQL, SQL Server, etc.)

Hibernate converts Java objects into database records automatically.

3. Why Hibernate is Preferred for ORM

Hibernate is widely preferred because it provides:

Feature	Benefit
Automatic Mapping	Reduces manual SQL coding
Database Independence	Works with multiple databases
Performance Optimization	Uses caching and lazy loading
HQL Support	Object-oriented query language
Transaction Management	Simplifies transaction handling
Relationship Mapping	Handles OneToOne, OneToMany, ManyToMany
Integration with Spring	Easy enterprise integration
Reduced Boilerplate Code	Faster development

```java
package com.hibernate.entity;

import jakarta.persistence.Entity;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

@Entity
@Table(name = "student")
public class Student {

    @Id
    private int id;

    private String name;

    private String course;

    // Default Constructor
    public Student() {
    }

    // Parameterized Constructor
    public Student(int id, String name, String course) {
        this.id = id;
        this.name = name;
        this.course = course;
    }

    // Getters and Setters

    public int getId() {
        return id;
    }

    public void setId(int id) {
        this.id = id;
    }

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }

    public String getCourse() {
        return course;
    }

    public void setCourse(String course) {
        this.course = course;
    }

    @Override
    public String toString() {
        return "Student{" +
                "id=" + id +
                ", name='" + name + '\'' +
                ", course='" + course + '\'' +
                '}';
    }
}
```

```java
package com.hibernate.util;

import org.hibernate.SessionFactory;
import org.hibernate.cfg.Configuration;

public class HibernateUtil {

    private static SessionFactory sessionFactory;

    static {
        try {
            sessionFactory = new Configuration()
                    .configure("hibernate.cfg.xml")
                    .buildSessionFactory();

        } catch (Exception e) {
            e.printStackTrace();
        }
    }

    public static SessionFactory getSessionFactory() {
        return sessionFactory;
    }
}
```

## App.java

```java
package com.hibernate.main;

import com.hibernate.entity.Student;
import com.hibernate.util.HibernateUtil;
import org.hibernate.Session;
import org.hibernate.Transaction;

public class App {

    public static void main(String[] args) {

        Session session = null;
        Transaction transaction = null;

        try {

            // Open Session
            session = HibernateUtil
                    .getSessionFactory()
                    .openSession();

            // Start Transaction
            transaction = session.beginTransaction();

            // Create Object
            Student student = new Student();

            student.setId(101);
            student.setName("Amol");
            student.setCourse("Java Full Stack");

            // Save Object
            session.persist(student);

            // Commit Transaction
            transaction.commit();

            System.out.println("Student record inserted successfully");

            // Verify Data
            Student fetchedStudent = session.get(Student.class, 101);

            System.out.println("Fetched Record:");
            System.out.println(fetchedStudent);

        } catch (Exception e) {

            if (transaction != null) {
                transaction.rollback();
            }

            e.printStackTrace();

        } finally {

            if (session != null) {
                session.close();
            }
        }
    }
}
```
