Introduction to ‘Spring MVC’ module :

What is Spring MVC?

Spring Framework MVC stands for:

M → Model 
V → View
C → Controller

Spring MVC is a Java-based web framework used to develop:

Web applications
REST APIs
Enterprise applications

It follows the Model-View-Controller design pattern to separate application logic from presentation logic.

Why Spring MVC?

Before Spring MVC, developers used:

Servlets
JSP
Struts

Problems with traditional Servlets:

Large and complex code
Difficult maintenance
Tight coupling
Manual request handling

Spring MVC solves these problems by providing:

✅ Loose coupling
✅ Clean architecture
✅ Easy testing
✅ Reusable components
✅ Annotation-based programming
✅ Integration with Spring Boot

Real-Time Example

Example: 	Online Shopping Website

Component	Responsibility

Model		Product data, customer data
View		HTML/JSP pages
Controller		Handles user requests

Flow:

User opens website
Controller receives request
Controller calls service/business logic
Model fetches data
View displays result

Core Components of Spring MVC :

1. DispatcherServlet

The DispatcherServlet is the heart of Spring MVC.

It acts as:

Front Controller
Central request handler

Responsibilities:

Receives all requests
Sends request to appropriate controller
Gets response
Returns view to client

Example:

<servlet>
    <servlet-name>spring</servlet-name>
    <servlet-class>
        org.springframework.web.servlet.DispatcherServlet
    </servlet-class>
</servlet>

<servlet-mapping>
    <servlet-name>spring</servlet-name>
    <url-pattern>/</url-pattern>
</servlet-mapping>

2. Controller

Controller handles incoming HTTP requests.

It contains business request handling logic.

Example:

@Controller Annotation
public class HomeController {

    @RequestMapping("/home") URL  localhost:8080/home   DispatcherServlet -> Controller
    public String homePage() {
        return "home";
    }
}

Explanation:

@Controller → Marks class as controller
@RequestMapping → Maps URL
"home" → JSP page name

3. Model

Model stores application data. Database

Example:

model.addAttribute("name", "Amol"); 

Data is transferred from controller to view using Model.

4. View

View is the presentation layer. Client Side 

Examples:

JSP
HTML
Thymeleaf

Example JSP:

<h1>Welcome ${name}</h1>

5. View Resolver

View Resolver maps logical view names to actual view files.

Example: beans.xml

<bean class="org.springframework.web.servlet.view.InternalResourceViewResolver">

    <property name="prefix" value="/WEB-INF/views/" />
    <property name="suffix" value=".jsp" /> home.jsp

</bean>

If controller returns:

return "home";

Actual page becomes:

/WEB-INF/views/home.jsp

Front Controller in Spring MVC :


1. What is a Front Controller?

A Front Controller is a design pattern used in web applications where all incoming client requests are handled by a single centralized controller.

Instead of sending requests to different servlets directly, every request first goes to one central controller, which:

Receives the request
Decides what to do
Calls appropriate business logic
Selects the view
Sends response back to client

In Spring MVC, the Front Controller is implemented using:

DispatcherServlet

2. Why Do We Need Front Controller?

Without Front Controller:

Client → Servlet1 get request post request
Client → Servlet2
Client → Servlet3

Problems:

Duplicate code
Difficult request handling
No centralized validation/security/logging
Hard to maintain

With Front Controller:

Client → DispatcherServlet → Controller → Service → View

Advantages:

Centralized request handling
Easy security implementation
Better maintainability
Reusable processing
Loose coupling

package com.example.config;

import javax.sql.DataSource;

import org.springframework.context.annotation.Bean;

import org.springframework.context.annotation.Configuration;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.datasource.DriverManagerDataSource;
import org.springframework.web.servlet.ViewResolver;
import org.springframework.web.servlet.config.annotation.EnableWebMvc;
import org.springframework.web.servlet.view.InternalResourceViewResolver;

@Configuration
@EnableWebMvc
@ComponentScan(basePackages = "com.example")
public class SpringConfig {

    @Bean
    public ViewResolver viewResolver() {

        InternalResourceViewResolver resolver =
                new InternalResourceViewResolver();

        resolver.setPrefix("/WEB-INF/views/");
        resolver.setSuffix(".jsp");

        return resolver;
    }

    @Bean
    public DataSource dataSource() {

        DriverManagerDataSource ds =
                new DriverManagerDataSource();

        ds.setDriverClassName("com.mysql.cj.jdbc.Driver");
        ds.setUrl("jdbc:mysql://localhost:3306/springmvcdb");
        ds.setUsername("root");
        ds.setPassword("root");

        return ds;
    }

    @Bean
    public JdbcTemplate jdbcTemplate() {
        return new JdbcTemplate(dataSource());
    }
}
9️⃣ Create DAO Class
EmployeeDAO.java
package com.example.dao;

import java.util.List;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.jdbc.core.BeanPropertyRowMapper;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.stereotype.Repository;

import com.example.model.Employee;

@Repository
public class EmployeeDAO {

    @Autowired
    private JdbcTemplate jdbcTemplate;

    // INSERT
    public int save(Employee emp) {

        String sql = "INSERT INTO employee(name,email,department,salary) VALUES(?,?,?,?)";

        return jdbcTemplate.update(sql,
                emp.getName(),
                emp.getEmail(),
                emp.getDepartment(),
                emp.getSalary());
    }

    // UPDATE
    public int update(Employee emp) {

        String sql = "UPDATE employee SET name=?,email=?,department=?,salary=? WHERE id=?";

        return jdbcTemplate.update(sql,
                emp.getName(),
                emp.getEmail(),
                emp.getDepartment(),
                emp.getSalary(),
                emp.getId());
    }

    // DELETE
    public int delete(int id) {

        String sql = "DELETE FROM employee WHERE id=?";

        return jdbcTemplate.update(sql, id);
    }

    // GET SINGLE
    public Employee getEmployeeById(int id) {

        String sql = "SELECT * FROM employee WHERE id=?";

        return jdbcTemplate.queryForObject(
                sql,
                new Object[]{id},
                new BeanPropertyRowMapper<>(Employee.class)
        );
    }

    // GET ALL
    public List<Employee> getAllEmployees() {

        String sql = "SELECT * FROM employee";

        return jdbcTemplate.query(
                sql,
                new BeanPropertyRowMapper<>(Employee.class)
        );
    }
}
🔟 Create Controller Class
EmployeeController.java
package com.example.controller;

import java.util.List;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.*;

import com.example.dao.EmployeeDAO;
import com.example.model.Employee;

@Controller
public class EmployeeController {

    @Autowired
    private EmployeeDAO employeeDAO;

    // Home Page
    @GetMapping("/")
    public String home(Model model) {

        List<Employee> employees =
                employeeDAO.getAllEmployees();

        model.addAttribute("employees", employees);

        return "employeelist";
    }

    // Show Form
    @GetMapping("/addEmployee")
    public String addEmployeeForm(Model model) {

        model.addAttribute("employee", new Employee());

        return "employeeform";
    }

    // Save Employee
    @PostMapping("/saveEmployee")
    public String saveEmployee(@ModelAttribute Employee employee) {

        employeeDAO.save(employee);

        return "redirect:/";
    }

    // Edit Form
    @GetMapping("/editEmployee/{id}")
    public String editEmployee(@PathVariable int id,
                               Model model) {

        Employee employee =
                employeeDAO.getEmployeeById(id);

        model.addAttribute("employee", employee);

        return "editemployee";
    }

    // Update Employee
    @PostMapping("/updateEmployee")
    public String updateEmployee(@ModelAttribute Employee employee) {

        employeeDAO.update(employee);

        return "redirect:/";
    }

    // Delete Employee
    @GetMapping("/deleteEmployee/{id}")
    public String deleteEmployee(@PathVariable int id) {

        employeeDAO.delete(id);

        return "redirect:/";
    }
}

View Resolver bean :

In Spring Framework MVC, a View Resolver is responsible for mapping the logical view name returned by the controller to the actual physical view page (JSP, HTML, Thymeleaf template, etc.).

It helps Spring decide:

Which view technology to use home.jsp, employee.jsp
Where the view files are located  views
What file extension should be added   .html, .jsp. .themeleaf

1. Why View Resolver is Needed

Suppose a controller returns:

return "home";

Spring does not know:

Where home.jsp exists

Whether it is JSP, Thymeleaf, or another template

The View Resolver converts:

home

into:

/WEB-INF/views/home.jsp

2. Flow of View Resolver in Spring MVC

Client Request
      ↓
DispatcherServlet
      ↓
Controller
      ↓
Returns Logical View Name
      ↓
View Resolver
      ↓
Maps to Actual JSP/HTML Page
      ↓
View Rendered to Browser

3. Components Involved

Component	Purpose

Controller		Returns logical view name
DispatcherServlet	Receives request
ViewResolver	Finds actual view
View		JSP/HTML page shown to user

1. What is Handler Mapping in Spring MVC?

Definition

Handler Mapping is a Spring MVC component that maps an incoming HTTP request URL to the appropriate Controller method.

It tells the DispatcherServlet:

“Which controller should handle this request?”

Role of Handler Mapping

When a request comes:

http://localhost:8080/student/home

The DispatcherServlet asks Handler Mapping:

Which controller method matches /student/home ?

Handler Mapping finds the matching controller method and returns it.

Internal Flow

Client Request
      ↓
DispatcherServlet
      ↓
HandlerMapping
      ↓
Finds Controller Method
      ↓
Controller Executes
      ↓
Returns View

Types of Handler Mapping

Handler Mapping Type		Description

BeanNameUrlHandlerMapping		Maps URL with bean name
SimpleUrlHandlerMapping		Maps URL using properties
RequestMappingHandlerMapping	Modern annotation-based mapping

Most modern Spring MVC applications use:

@RequestMapping
@GetMapping
@PostMapping

which internally use:

RequestMappingHandlerMapping

13. Manual Validator Example

Custom Validator

EmployeeValidator.java

package com.demo.validator;

import com.demo.model.Employee;
import org.springframework.validation.Errors;
import org.springframework.validation.Validator;

public class EmployeeValidator implements Validator {

    @Override
    public boolean supports(Class<?> clazz) {
        return Employee.class.equals(clazz);
    }

    @Override
    public void validate(Object target, Errors errors) {

        Employee emp = (Employee) target;

        if(emp.getName().length() < 3) {
            errors.rejectValue(
                    "name",
                    "name.error",
                    "Name must contain minimum 3 characters"
            );
        }
    }
}

Using Custom Validator in Controller

@PostMapping("/saveEmployee")
public String saveEmployee(
        Employee employee,
        BindingResult result) {

    EmployeeValidator validator =
            new EmployeeValidator();

    validator.validate(employee, result);

    if(result.hasErrors()) {
        return "register";
    }

    return "success";
}
